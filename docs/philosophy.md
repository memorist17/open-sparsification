# OpenSparsity: 地理空間データによる都市構造特性分析基盤

## ビジョンと使命
OpenSparsityは、都市を「連続的に変化する複合ネットワーク」として捉え、地理空間データから得られる指標を公共政策・研究・市民活動の意思決定に還元することを目指しています。都市全体の構造を透明化し、地域ごとの潜在力や課題を誰もが議論できる土台を提供する――これがプロジェクトの中心的なモチベーションです。

- 都市の状態を単発のレポートではなく継続的に把握できるオープンプラットフォームを構築する
- 統計モデルや機械学習アルゴリズムをブラックボックスにせず、前提・限界・解釈を共有する
- 研究者・自治体・市民が同じ指標を使って対話できる共通語を整備する

## 解きたい都市の課題
都市は人口動態、インフラ更新、モビリティサービス、災害リスクなど多層の要因が絡み合う動的なシステムです。既存の分析は個別テーマに閉じがちで、複合的な視点が不足しています。OpenSparsityは次のようなギャップに焦点を当てています。

- **スケールの分断**: マクロな統計とミクロな現地観察の間を埋める指標が乏しい
- **データとストーリーの断絶**: 数値成果が都市像や政策仮説に結び付かず、意思決定がブラックボックス化する
- **再現性の欠如**: 同じ分析を他都市・他時点に展開できないため、比較と学習が進まない

## 設計思想

### 🔄 再現性 (Reproducibility)
都市分析はデータの更新頻度や取得条件によって結果が揺らぎます。その揺らぎを説明可能にするため、分析環境を完全にコンテナ化し、コード・データ・設定のバージョンを追跡します。Dockerベースのワークフローと明示的な依存関係管理により、別拠点の研究者や自治体でも同一条件で分析を再実行できます。

### 🧩 モジュール性 (Modularity)
都市テーマごとに仮説や分析手法が異なるため、パイプラインをコンポーネント単位で差し替えられるよう設計しています。データ取得、前処理、指標算出、可視化を疎結合化し、特定都市・特定課題に合わせたアダプテーションを最小限の変更で行えるようにしています。

### ⚙️ 設定駆動 (Configuration-Driven)
分析条件をコードに埋め込むと再現性が損なわれます。OpenSparsityでは、セグメントの閾値やクラスタリングのパラメータなどはすべて設定ファイル化し、実験ログとセットで共有します。これにより、指標の値が変化した理由をパラメータの差異から説明でき、共同研究が円滑になります。

### 📚 ドキュメント先行 (Documentation-First)
都市仮説や評価指標の背景が言語化されていないと、可視化結果の誤読が生じます。アルゴリズム・データソース・解釈上の注意点をドキュメントに先に落とし込み、実装はそれに追従させる方針を採っています。開発者だけでなく、政策担当者や市民研究者がドキュメントを通じてプロジェクトの前提を共有できる状態を目指しています。

## 指標というレンズ
OpenSparsityが採用する都市指標は、都市を多中心的で適応的なシステムとみなす視座を表しています。各指標は単独で完結するものではなく、組み合わせることで都市の「状態」を立体的に描写します。

#### 多中心性
DBSCANで抽出した活動クラスターの分布を分析し、都市が複数の重心を持つか、単一中心に偏るかを測定します。交通・商業・生活の重心がどの程度分散しているかは、レジリエンスや生活の多様性に直結する要素です。

#### 疎性
道路・建物ネットワークがどれだけ空間を埋めているかを、密度と連結性の関係から評価します。疎な地域は余白としての潜在力を持つ一方、公共サービスのアクセスに課題が生じる可能性もあるため、政策仮説との紐付けが不可欠です。

#### 流動性
パーコレーション分析でネットワークの臨界点を探り、都市内の移動がどこで途切れるかを測定します。モビリティ施策やインフラ投資の優先順位を議論する際の根拠となる指標です。

#### 重なり
用途や属性が異なる建物群がどれだけ共存しているかを定量化し、地域の機能的多様性を捉えます。単機能化した地区では、災害や市場変動に対する脆弱性が高まる可能性があります。

#### 創発性
ネットワーク中心性と密度の関係性から、局所的な振る舞いが都市全体にどのようなパターンをもたらすかを読み解きます。予想外の活動拠点や、自律的に発展するエリアを抽出する手がかりとなります。

#### 適応性
Fiedler値を用いたグラフ分解によって、ネットワークがどれだけ柔軟に再構成できるかを評価します。インフラ障害や災害発生時の迂回可能性を定量的に議論する際に活用します。

## データと倫理・透明性
- 行政オープンデータやOpenStreetMap等のデータソースについて、利用条件・更新タイミング・精度の限界を明記し、利用者が二次利用時に誤解しないよう配慮します。
- 住民属性などセンシティブな情報を扱う場合は、空間解像度の制御や匿名化手法を組み合わせ、個人の特定を防ぎます。
- 指標の公表は都市の評価につながるため、データ解釈が偏らないよう、背景説明とともに結果を提示します。

## コミュニティと貢献のスタンス
オープンソースとしての透明性を保ちながら、現場知と研究知の循環を促すため、以下の方針でコミュニティ運営を行います。
- Issueでは課題の背景と期待するアウトカムを明記し、議論の文脈を共有する
- Pull Requestでは指標や可視化に関する検証方法・解釈を必ず添える
- ワークショップやフィールドワークの知見をドキュメントに反映し、コードに還元する

## 研究との接続
OpenSparsityは都市を複雑系として扱う研究潮流を土台にしています。Batty (2007)の都市複雑性の議論からは、マルチスケールなネットワーク分析のフレームを継承しています。一方でRaimbault (2020)の人工生命的アプローチからは、都市を今後どうあるべきかという設計的思考を学び、指標を未来志向のシミュレーションにも活用する姿勢を取り入れています。これらの先行研究を踏まえつつ、日本の都市文脈に合わせた実証データと分析基盤を提供する点がOpenSparsityの独自性です。
