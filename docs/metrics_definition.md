# 指標定義と計算式

## 概要

OpenSparsityプロジェクトで使用する集落構造特性指標の定義、計算式、および`parameters.yml`で設定可能なパラメータについて説明します。

**設計思想との関係:**

各指標は、集落を多中心的で適応的なシステムとみなす視座を表しています（`docs/philosophy.md`参照）。指標は単独で完結するものではなく、組み合わせることで集落の「状態」を立体的に描写します。

## 1. 多中心性 (Multi-nodality)

### 定義
集落空間における複数の中心（核）の存在とその分布特性を定量化する指標。DBSCANで抽出した活動クラスターの分布を分析し、集落が複数の重心を持つか、単一中心に偏るかを測定します。

### 哲学的背景
交通・商業・生活の重心がどの程度分散しているかは、レジリエンスや生活の多様性に直結する要素です。多中心的な集落は、一箇所の機能停止が全体に波及しにくく、多様な生活様式を許容します。

### 計算式
```
多中心性 = 核の数 × 核の分散度 × 核の多様性
```

### 計算手順
1. **DBSCANクラスタリング**: 建物密度の高い地点をクラスターとして検出
2. **核の数**: 検出されたクラスター数
3. **核の分散度**: クラスター間の距離の分散
4. **核の多様性**: クラスターサイズの多様性（シャノン多様性指数）

### 設定パラメータ
```yaml
multi_nodality:
  dbscan:
    eps: 0.5              # クラスター半径（度）
    min_samples: 5        # 最小サンプル数
    metric: "euclidean"   # 距離メトリック
  dispersion:
    method: "variance"    # 分散度計算方法
  diversity:
    method: "shannon"     # 多様性計算方法
```

## 2. 疎性 (Sparsity)

### 定義
空間の充填度と建物数の関係から集落の密度特性を評価する指標。道路・建物ネットワークがどれだけ空間を埋めているかを、密度と連結性の関係から評価します。

### 哲学的背景
疎な地域は余白としての潜在力を持つ一方、公共サービスのアクセスに課題が生じる可能性もあるため、政策仮説との紐付けが不可欠です。高密度と低密度は価値中立的であり、文脈依存的な解釈が求められます。

### 計算式
```
疎性 = 空間充填率（フラクタル次元数） / 建物数
```

### 計算手順
1. **フラクタル次元計算**: ボックスカウンティング法による空間充填率
2. **建物数カウント**: 指定面積以上の建物数を計算
3. **疎性指標**: フラクタル次元を建物数で正規化

### 設定パラメータ
```yaml
sparsity:
  fractal:
    method: "box_counting"
    box_sizes: [1, 2, 4, 8, 16, 32, 64]  # ボックスサイズ（メートル）
  building_count:
    min_area: 10.0        # 最小建物面積（m²）
```

## 3. 流動性 (Permeability)

### 定義
オープンスペースの連結性を通じて集落の移動可能性を評価する指標。パーコレーション分析でネットワークの臨界点を探り、集落内の移動がどこで途切れるかを測定します。

### 哲学的背景
モビリティ施策やインフラ投資の優先順位を議論する際の根拠となる指標です。流動性が低い地域は、移動手段の確保や経路の多様化が政策課題となります。

### 計算式
```
流動性 = 最大オープンスペース面積 / 全オープンスペースの総面積
```

### 計算手順
1. **空間離散化**: 指定グリッドサイズで空間を分割
2. **オープンスペース判定**: 建物密度閾値による判定
3. **パーコレーション解析**: 連結成分の分析
4. **流動性計算**: 最大連結成分の面積比率

### 設定パラメータ
```yaml
permeability:
  grid_size: 50.0                    # グリッドサイズ（メートル）
  open_space:
    building_density_threshold: 0.3  # 建物密度閾値
    min_road_width: 3.0              # 最小道路幅
    min_green_area: 100.0            # 最小緑地面積
  percolation_threshold: 0.5927      # パーコレーション閾値
```

## 4. 重なり (Overlap)

### 定義
複数の機能や属性を持つ建物の割合を評価する指標。用途や属性が異なる建物群がどれだけ共存しているかを定量化し、地域の機能的多様性を捉えます。

### 哲学的背景
単機能化した地区では、災害や市場変動に対する脆弱性が高まる可能性があります。混在する機能は、相互補完的なレジリエンスを生み出す可能性があります。

### 計算式
```
重なり = 複数の属性をもった建物総数 / 総建物数
```

### 計算手順
1. **属性分類**: 建物を住宅、商業、工業、公共に分類
2. **重複判定**: 複数属性を持つ建物を特定
3. **重なり計算**: 重複建物の割合

### 設定パラメータ
```yaml
overlap:
  attributes:
    - "residential"  # 住宅
    - "commercial"   # 商業
    - "industrial"   # 工業
    - "public"       # 公共
  overlap_threshold: 0.1  # 重複判定閾値
```

## 5. 創発性 (Emergence)

### 定義
ネットワーク中心性と建物密度の関係から、集落空間における創発的現象の可能性を評価する指標。ネットワーク中心性と密度の関係性から、局所的な振る舞いが集落全体にどのようなパターンをもたらすかを読み解きます。

### 哲学的背景
予想外の活動拠点や、自律的に発展するエリアを抽出する手がかりとなります。中心性が高く密度が低い場所は、新しい機能が生まれる潜在力を持つ可能性があります。

### 計算式
```
創発性 = (各余白地点のネットワーク中心性 / (1 + 建物密度))の平均
```

### 計算手順
1. **ネットワーク構築**: 建物間の接続関係を構築
2. **中心性計算**: 各地点のネットワーク中心性を計算
3. **密度正規化**: 建物密度で正規化
4. **創発性計算**: 正規化された中心性の平均

### 設定パラメータ
```yaml
emergence:
  centrality:
    - "betweenness"  # 媒介中心性
    - "closeness"    # 近接中心性
    - "eigenvector"  # 固有ベクトル中心性
  density:
    radius: 200.0    # 密度計算半径（メートル）
    method: "gaussian"  # 密度計算方法
```

## 6. レジリエンス / 適応性 (Resilience)

### 定義
ネットワークのFiedler値（代数的連結度）を用いて集落の適応性・レジリエンスを評価する指標。Fiedler値を用いたグラフ分解によって、ネットワークがどれだけ柔軟に再構成できるかを評価します。

### 哲学的背景
インフラ障害や災害発生時の迂回可能性を定量的に議論する際に活用します。値が高いほど、ネットワークが分断されにくく、多様な経路で再接続可能であることを示します。

### 計算式
```
適応性 = Fiedler値（グラフの代数的連結度）
```

### 計算手順
1. **ネットワーク構築**: 建物・道路の接続関係を構築
2. **ラプラシアン行列**: グラフのラプラシアン行列を計算
3. **固有値計算**: ラプラシアン行列の固有値を計算
4. **Fiedler値**: 2番目に小さい固有値（Fiedler値）を取得

### 設定パラメータ
```yaml
resilience:
  fiedler:
    distance_threshold: 100.0  # グラフ構築閾値（メートル）
    weight_method: "distance"  # 重み付け方法
  network_type:
    - "road"      # 道路ネットワーク
    - "building"  # 建物ネットワーク
    - "mixed"     # 混合ネットワーク
```

## パラメータ設定のガイドライン

### 1. スケール依存性
- **グリッドサイズ**: 分析対象のスケールに応じて調整
- **距離閾値**: 集落の密度と広がりに応じて調整
- 集落の空間スケールは文脈依存的であり、パラメータは分析対象に合わせて慎重に設定する必要があります

### 2. データ品質
- **最小面積**: データの解像度に応じて調整
- **密度閾値**: 地域特性に応じて調整
- データソースの更新頻度や取得条件を明記し、結果の揺らぎを説明可能にすることが重要です

### 3. 計算効率
- **並列処理**: CPU数に応じて調整
- **キャッシュ**: メモリ使用量に応じて調整
- 大規模データセットでは、チャンク処理やキャッシュ戦略の検討が必要です

### 4. 再現性の確保
- すべてのパラメータは `config/parameters.yml` で一元管理されています
- 分析条件をコードに埋め込まず、実験ログとセットで共有することで再現性を確保します
- 乱数シード (`random_seed`) を設定することで、サンプリングの再現性を保証します

## 設定駆動アーキテクチャ

OpenSparsityでは、分析条件をコードに埋め込まず、設定ファイルで管理しています：

- **`config/parameters.yml`**: 指標計算のパラメータ
- **`config/dashboard.yml`**: ダッシュボード表示のパラメータ

これにより、コード変更なしで分析条件を変更でき、研究の前提条件を透明化します。
